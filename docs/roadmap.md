# 待开发路线（Roadmap）

本文件是 TeachAIAgent（后端 `teachai-agent-api` + 前端 `teachai-agent-web`）唯一的待办清单来源。完成一项就在这里更新状态，不要只写在对话里。

## 当前状态

阶段 1–6D 全部完成并已生产联调：认证与邮箱验证码注册、课程/文件夹与本地素材（上传、解析、检索、鉴权下载）、用户级 Provider 配置与真实连接测试、版本化课程大纲、课堂 DSL 与沉浸式播放器、旁白合成、课堂配图（Qwen Image + 免费兜底）、课堂导出（PPTX 保真版 + 单文件 HTML）、Docker + 宿主 Nginx + TLS 生产部署。

最近一次语义调整（已实现并测试）：

- 生成默认固定使用本地 `llama-local`（`Qwen3.6-35B-A3B`），只有用户在设置页勾选「使用当前模型」并保存后才切换到该 Provider。
- 不勾选时仅保存配置信息，不做多厂商链式兜底；本地模型不可用时对已保存配置单次回退一次。
- 响应解析失败不换厂商，同厂商重试一次。

回归基线：后端 `pytest` 140 passed、`ruff`/`mypy` 干净；前端 `typecheck`/`lint` 通过、`vitest` 66 passed。任何新功能都必须在这条基线上不退化。

## 非目标（明确不做）

- 不保留原 OpenMAIC 的教师 / 助教 / 学生多 Agent 体系：`teachai` 只需单 Agent 的「教师」角色，供用户对话、互动提问与解答。
- 不做学生端独立身份与班级/作业流转（当前所有资源都按 owner 隔离）。
- 不做自动挑选具体模型替用户决策：换模型只能由用户改对应厂商的配置并显式勾选。
- 不引入多租户组织/团队协作模型，除非另行拍板。

## P0：用户输入文本清洗补全

现状：模型输出侧已经在落库前统一走 `app/core/text.py` 的 `sanitize_text` / `sanitize_json`，但用户输入的文本没有。用户提交含 `0x00` 的字符串时，`asyncpg` 抛 `CharacterNotInRepertoireError`，接口 500。

待覆盖入口：

- 建课 / 改课：`title`、`description`。
- 文件夹名称。
- 手工保存大纲（`PUT` 大纲）里的标题与场景文本。
- 对话功能新增的消息内容（实现时同步接入）。

验收：向上述每个入口提交含 `\x00`、未配对代理项、超长空白的文本，均返回 200/201 且落库内容已被清洗；现有 140 + 66 条测试不退化。

## P1：课堂内「用户 ↔ 教师」对话问答

目标：用户在课堂/课程里可以就当前内容向「教师」提问并获得解答，保持现有单 Agent 架构与 Provider 语义。

待拍板的设计决策（开发前必须先与用户确认）：

1. 入口形态：课堂播放器右侧抽屉、课程档案页独立区块、还是 `/course/[id]/chat` 独立页面。
2. 上下文范围：仅当前场景、整节课大纲 + 全部场景，还是要带上课程素材全文（影响 token 预算与成本）。
3. 返回方式：普通 JSON 一次性返回，还是 SSE 流式逐字输出（本机 llama.cpp 为明文 HTTP，流式要注意 Nginx/隧道缓冲）。
4. 会话模型：每个课程一条长会话，还是每次进入课堂新建会话；是否需要「历史会话列表」。
5. 持久化：消息是否入库、保留多久、是否允许用户删除单条消息。
6. 教师行为：只答不追问，还是允许教师主动追问/出题；是否需要「引用来源」（第几页素材、第几个场景）。
7. 模型与限额：沿用「默认本地模型 + 用户勾选才切换」；单条消息长度、单课程每日调用上限是否需要。
8. 移动端形态：是否需要与桌面一致的抽屉，或退化为底部弹层。
9. 与生成任务的关系：对话是否复用 `POST /api/v1/generation/jobs` 的异步任务模型（长回答）还是独立同步/流式接口。

建议的后端落点（供拍板参考）：新增 `app/api/routes/chat.py` 与 `app/services/chat.py`，上下文由 `classroom` / `outline` 现有服务组装，模型调用复用 `app/services/llm.py`，Provider 解析复用 `ProviderConfigService.resolve_for_generation`；新增表 `course_chat_sessions` / `course_chat_messages`，务必走 Alembic 迁移并保证对已部署库向前兼容。

验收：能围绕当前课堂内容连续问答；答案与上下文一致；默认走本地模型、切换逻辑与设置页一致；刷新页面后历史可恢复（若选择持久化）；移动端可用；P0 与既有测试全部保持通过。

## P2：体验与稳定性

- 任务队列：当前生成任务用 FastAPI `BackgroundTasks` 在进程内执行，进程重启会中断（已有 `recover_interrupted_jobs` 兜底标记失败）。可评估独立 worker + 队列（Redis/RQ 或 arq）以支持多副本与重试。
- 公网接入：`cpolar` 免费额度带宽与稳定性有限，长任务易断流；建议换 frp TCP 透传或内网 443 端口映射。
- 配图质量：引入图片质量评估与可选正式图片服务商（当前 Qwen Image 主通道 + 免费兜底）。
- 导出体验：确认移动端 PPTX 逐条动画与 HTML 交互组件在更多浏览器上的表现，补齐回归用例。
- 运维可观测：结构化日志已具备 `request_id`，可补任务耗时与 Provider 调用失败率的聚合。
